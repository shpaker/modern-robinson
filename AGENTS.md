# Разработка modern-robinson

Файл для агентов, которые работают с исходниками ремейка. Правила
разработки — в [ARCHITECTURE.md](ARCHITECTURE.md), раздел «Правила».
Агенту в папке игры — свой файл, [packaging/AGENTS.md](packaging/AGENTS.md):
он уходит в архив релиза.

## Игра через MCP

- Не играть из этой папки: здесь исходники, `docs/` и распакованные ресурсы
  игры — решения видны, а это читерство.
- Мост не нужен: MCP-серверы подключаются при старте сессии. Играют из папки
  игры: в ней `.mcp.json` из архива ([packaging/.mcp.json](packaging/.mcp.json))
  и новая сессия там; или `claude mcp add` с путём к папке игры; не
  подключилось — скилл [skills/robinson](skills/robinson/SKILL.md). Мост ещё
  и вреден: через Bash можно гонять циклы-переборы, а из папки исходников
  видны решения.
- Честная игра — как в инструкциях сервера (`internal/adapters/mcp`): не
  перебирать; причина каждого действия — в чат до вызова, следствие — после
  ответа.
- Проверить MCP при разработке — тоже без моста:
  - юнит-тесты `internal/adapters/mcp` подключают клиента к серверу прямо в
    процессе;
  - целиком — вложенная сессия из пустой временной папки:
    `claude -p "…" --mcp-config robinson.json --strict-mcp-config
    --allowedTools mcp__robinson`, где в `robinson.json` — тот же
    `mcpServers.robinson`, что в `.mcp.json`. Это настоящий MCP-клиент: свой
    сервер и своё окно игры на всю вложенную сессию;
  - `.mcp.json` архива — во временной папке игры: копия ресурсов (`cp -cR`,
    не симлинки: они ломают индекс ресурсов) и распакованный `just release`.
    В ней `claude -p "…" --output-format stream-json --verbose`: в событии
    `system` у `robinson` должно быть `connected`.
