# Новый Робинзон

Реверс-инжиниринг и ремейк квеста «Новый Робинзон» (Никита, 1999) на
**Go + Ebitengine**. Форматы игры вскрыты, ремейк — новый интерпретатор
оригинальных ресурсов. Работает на macOS, Linux, Windows и в браузере.

Репозиторий — <https://github.com/shpaker/modern-robinson>, готовые сборки —
[Releases](https://github.com/shpaker/modern-robinson/releases).

> Ассетов игры нет ни в репозитории, ни в архиве релиза — нужна своя копия
> игры (диск или его образ).

## Как запустить

Ресурсы читаются из папки игры напрямую, конвертировать ничего не нужно.

**1. Скопировать игру в папку.** Всё содержимое диска или образа `ROBINSON.iso`
скопировать в обычную папку, куда можно писать: игра кладёт туда сохранения, и
с самого диска или подключённого образа они не запишутся. В Windows и macOS
образ открывается двойным щелчком. На Linux — `7z x ROBINSON.iso -oRobinson`:
имена файлов должны остаться заглавными, как на диске, а обычный `mount`
показывает их строчными (если монтировать, то с `-o map=off`). В папке должна
оказаться `DATA/WAVE/WAVE.DAN`.

**2. Взять сборку** со страницы
[Releases](https://github.com/shpaker/modern-robinson/releases) — архив
`modern-robinson_<версия>.zip`, один на все системы. В нём одна папка:
бинарники всех трёх систем, запускалка `robinson` (сама выбирает сборку macOS
или Linux), `README.md`, `THIRD_PARTY.md`, образец настроек `config.yml`, для
агента в папке игры — `AGENTS.md` (правила) и `.mcp.json` (MCP-сервер игры),
тексты ролей `roles/` и скилл `skills/robinson` (см.
[«Игра через MCP»](#игра-через-mcp)).

| Система | Бинарник |
|---|---|
| Windows x64 | `robinson.exe` |
| macOS на Apple Silicon (M1 и новее) | `robinson_darwin_arm64` |
| Linux x86-64 (glibc 2.34+) | `robinson_linux_amd64` |

Всё из папки архива переложить прямо в папку игры, рядом с `DATA`, а не во
вложенную папку, и запустить бинарник своей системы (на macOS и Linux — или
`robinson`). `.mcp.json` — скрытый файл, и «выделить всё» его пропускает:
скрытые файлы в Finder показывает Cmd+Shift+., в файловых менеджерах Linux —
Ctrl+H; или скопировать всё из терминала:
`cp -R modern-robinson_<версия>/. /путь/к/папке/`. Можно переложить и только
бинарник (при желании — с `config.yml`): бинарники других систем не нужны, но
и не мешают. Или запустить откуда угодно, передав путь:
`robinson_linux_amd64 /путь/к/папке`.

Сборки не подписаны. macOS при первом запуске откажется открыть файл: выполните
в папке игры `xattr -d com.apple.quarantine robinson robinson_darwin_arm64` или
нажмите «Всё равно открыть» в «Системные настройки → Конфиденциальность и
безопасность»; при запуске двойным щелчком откроется и окно Терминала — его не
закрывайте. Windows покажет SmartScreen: «Подробнее» → «Выполнить в любом
случае». Если папка игры не найдена, программа сразу закрывается (в терминале —
с ошибкой `game resources not found`).

**Из исходников** (Go 1.26+, [just](https://github.com/casey/just)):
```bash
just build
./robinson /путь/к/папке
```
Либо положить `robinson` прямо в папку игры и запустить без аргументов.
Кросс-сборки: `just build-macos|build-linux|build-windows` (все три —
`just build-all`), архив для раздачи, как в релизе, — `just release`.
Браузерная версия — [docs/11-web-build.md](docs/11-web-build.md).

## Управление

| | Мышь |
|---|---|
| Идти | клик по земле |
| Действие с объектом | клик по объекту |
| Предмет на себя | клик у ног героя, пока он стоит |
| Название объекта | навести курсор |
| Прокрутить сцену | курсор у левого или правого края |
| Сменить локацию | клик там, где курсор — стрелка: у краёв сцены, у дверей и проходов |
| Пропустить ролик | клик или клавиша, кроме Esc и F-клавиш |

Действие совершается предметом, выбранным в панели; «рука» — взять или сделать
самому. Камера сама за героем не следит: при ходьбе она едет к точке клика.
Пропускаются не все ролики, а только те, что игра разрешает прервать.

**Панель:** портрет — кто действует, Роби или Пятница (когда Пятница в
команде; предметы у каждого свои, по клику на землю идёт Роби), стрелки —
листать предметы, предмет — выбрать, карта — быстрый переход по острову (когда
карта открыта), дискета — главное меню.

**Клавиши:** **Esc** — главное меню (там же выход), **F5**/**F9** — быстрые
сохранение и загрузка (первый слот экрана сохранений). Отладка: **F1** — сетка
ходьбы, клик-зоны, пути и что сделает клик; **F2** — переменные квеста и
последние команды.

**Мини-игры:** **Esc** или кнопка в правом нижнем углу — выйти (у органа
кнопки нет, только Esc). В пазлах хижины и карты деталь берут и кладут кликом,
правая кнопка поворачивает деталь в руке. Орган:
расставить трубки и кликнуть по барабанщику — ответ проверяется, когда мелодия
доиграет; клик по Пятнице — он повторит арию, которую надо подобрать.
Воздушный шар: **↑**/**↓** или клик по Робинзону/Пятнице —
подняться/спуститься.

## Настройки

Необязательный `config.yml` в папке игры или рядом с бинарником (если есть
оба — берётся из папки игры). Пропущенный или непонятный ключ получает значение
по умолчанию, число вне диапазона — ближайшую границу; значения пишутся без
кавычек:

```yaml
scale: 2          # увеличение окна (окно игры 640×480), 1..4
sound: 1.0        # громкость звука, 0..1
music: 0.7        # громкость музыки, 0..1
speed: 0.5        # скорость игры, 0..1 (0.5 — как в оригинале)
debug: false      # запускать с отладочным слоем (он же F1)
fullscreen: false
```

Громкость и скорость меняются и в игре — в главном меню (**Esc**). Отпущенный
ползунок записывается в `config.yml` (остальные строки и комментарии не трогаются;
если файла нет, он появится в папке игры), так что следующий запуск начнётся с
тех же уровней. В браузерной сборке уровни живут только до закрытия вкладки.

## Игра через MCP

С флагом `-mcp` игра — MCP-сервер на stdin/stdout, и играет в неё модель
через MCP-клиент. Герои знают только то, что видит и слышит Роби: подписи
объектов, свои вещи, реплики, звуки головоломок и что изменилось после
действия; правила головоломок — как игрок, из руководства к игре. Сервер
отдаёт только данные, а говорят герои сами, своими словами.

**Кто играет.** Основная модель — координатор без голоса: передаёт ответы
игры сабагентам, их слова — сразу в чат и друг другу, решения Роби — в игру;
сама за героев не думает и не советует. Сабагенты:

- рассказчик — вне острова: говорит для игрока, когда сочтёт нужным, а герои
  его не слышат;
- Роби — решает, что делать; головоломки решает сам, по ходу за ответ;
- Пятница — когда он рядом: ответ игры приходит ему и Роби сразу, и они
  спорят, пока Роби не решит; решающий голос — у Роби.

У Роби и Пятницы по три шкалы от 0 до 10: симпатия друг к другу, к острову и
к спасению. Каждый пересматривает свои после каждого события; строка со
шкалами видна в чате, а другому герою — нет. Шкалы окрашивают слова и спор, а
когда желание спастись совсем падает, Роби может и отказаться выбираться —
тогда его придётся уговаривать. Клиент без сабагентов (Claude Desktop)
играет по-старому: модель сама играет Роби. С сабагентами игра заметно
дороже: на каждое действие — два-три их вызова.

**Роли** — тексты в папке `roles/` архива: `instructions.md` — инструкции
сервера (коротко: Claude Code режет их до 2048 символов), роли
`coordinator.md`, `narrator.md`, `robinson.md`, `friday.md` и общие для всех
`common.md` (как идёт партия, шкалы, честная игра), `world.md` (что приходит
от игры, инструменты) и `puzzles.md` (правила головоломок). Роль берут
инструментом `role`: её файл и общие подряд. Роли можно править: каждый файл
сервер ищет в `roles/` папки игры, потом рядом с бинарником, а недостающие у
него встроены. Новый файл — ещё одна роль для `role`; когда её звать, пишут в
`coordinator.md`.

**Честная игра.** Модель играет как игрок: файлы игры, исходники ремейка и
прохождения не читает, ходит только инструментами сервера, без своих скриптов
и перебора вариантов. Перед каждым действием в чате — зачем его делают, а
после ответа — что из него вышло. Это правило — в ролях.

**Что нужно.** Папка игры и сборка — шаги 1–2 из
[«Как запустить»](#как-запустить), на macOS — со снятым карантином. MCP-клиент,
который запускает серверы по stdio, — для игры сабагентами клиент с ними,
например Claude Code, — и модель, которая принимает картинки: головоломки
решаются по картинке экрана.

**Папка игры.** Если всё из архива лежит в папке игры, откройте в ней Claude
Code — `cd /путь/к/папке && claude` или новая сессия с этой папкой в
приложении — и разрешите сервер `robinson` из `.mcp.json` (не спросило —
`/mcp`, включить `robinson`). Окно игры откроется само, дальше просите модель
сыграть. Модель видит файлы вокруг, но читать их ей запрещают `AGENTS.md`
папки и роли сервера. `.mcp.json` запускает `./robinson -mcp`: в Windows
это `robinson.exe`, на macOS и Linux — запускалка, которая выбирает сборку
своей системы, а игру сервер ищет в папке, где открыт агент.

**Скилл** `skills/robinson` (в архиве релиза и в репозитории) — если сервер не
подключился или в папке игры нет `.mcp.json` (например, переложен только
бинарник): скилл проверит папку игры и сборку, запишет в папку игры
`.mcp.json` и попросит открыть в ней новую сессию — MCP-сервер подключается
только при её старте. В папке игры агент найдёт скилл сам, по `AGENTS.md`.
Чтобы звать его из любой папки, поставьте скилл один раз:

```bash
mkdir -p ~/.claude/skills
cp -r /путь/к/папке/skills/robinson ~/.claude/skills/
```

`/путь/к/папке` — папка игры, куда переложен архив, или папка из архива; в
Windows скилл кладётся в `%USERPROFILE%\.claude\skills\robinson`. Дальше в
Claude Code — `/robinson` или сразу с задачей, например
`/robinson накорми и напои Роби`: скилл спросит папку игры, если сессия
открыта не в ней, всё подготовит и попросит открыть новую сессию там.

**По прямому пути** — из любой папки и в других клиентах. Claude Code:

```bash
claude mcp add robinson -- /путь/к/папке/robinson -mcp
```

`robinson` — запускалка из архива в папке игры (в Windows — `robinson.exe`),
игру сервер найдёт рядом с ней. Если бинарник лежит не в папке игры, путь к
ней — после флага: `/путь/robinson_linux_amd64 -mcp /путь/к/папке`. Флаг
`-mcp` — строго до пути: после пути он уже не флаг, и игра запустится
обычной, без сервера. Без `--scope` сервер подключён только в текущей папке;
`--scope user` — во всех проектах, но тогда окно игры откроется в каждой
сессии. Только не в папке исходников ремейка: там модель нашла бы решения
головоломок, а не только то, что видит и слышит герой. Проверить — `/mcp` в
сессии.

**Claude Desktop** — в `claude_desktop_config.json` (Settings → Developer →
Edit Config; macOS — `~/Library/Application Support/Claude/`, Windows —
`%APPDATA%\Claude\`):

```json
{
  "mcpServers": {
    "robinson": {
      "command": "/путь/к/папке/robinson",
      "args": ["-mcp"]
    }
  }
}
```

Пути — полные, без `~`; в Windows — `robinson.exe`, а обратные слэши
удваиваются: `"C:\\Games\\Robinson\\robinson.exe"`. После правки приложение
перезапустить — выйти из него совсем, а не закрыть окно. Другим клиентам нужна
та же команда по stdio: `/путь/к/папке/robinson -mcp`.

**Как играть.** Окно игры открывается, когда клиент запускает сервер (Claude
Code — с началом сессии, Claude Desktop — с запуском приложения), и
закрывается вместе с ним. Партия каждый раз начинается сразу, без меню.
Попросите модель сыграть: рассказчик поздоровается, в чате пойдут мысли и
споры героев, а в окне видно, что они делают. Головоломка ждёт хода модели:
между её вызовами время в ней стоит, а ответ на ход приходит, когда
головоломка доиграла начатое.
Нажатие мыши или клавиши в окне пускает время головоломки как обычно (мышь
забирает и указатель) — до следующего хода модели.

**Кусок игры.** Можно попросить не всю игру, а кусок — например, «накорми и
напои Робинзона»: герои сделают это и остановятся, а дальше можно играть
самому, прямо в окне. Между их ходами можно и самому ходить в окне, и
подсказывать им словами.

| Инструмент | Параметры | Что делает |
|---|---|---|
| `role` | `who` | вне игры: роль — её файл из `roles/` и общие правила; `coordinator`, `narrator`, `robinson`, `friday` |
| `look` | `[image]`, `[grid]`, `[region]` | осмотреться: где ты, что вокруг, выходы, вещи; `image` — ещё картинка окна (в головоломке она приходит и так) |
| `use` | `target`, `[item]`, `why` | применить вещь из рук к тому, что вокруг, или к себе (`target` «себя»); `item` — сперва взять эту вещь |
| `go` | `to`, `why` | уйти через выход, на карте острова — в место |
| `map` | `why` | развернуть карту острова |
| `ask_friday` | `target`, `[item]`, `why` | попросить Пятницу применить её вещь |
| `wait` | `[seconds]`, `[grid]` | переждать сцену или подождать до 60 с; в головоломке — дать ей идти `seconds` секунд |
| `puzzle_click` | `x`, `y`, `[button]`, `[grid]`, `why` | клик по экрану головоломки 640×480, `button` — `left` или `right` |
| `puzzle_move` | `from_x`, `from_y`, `to_x`, `to_y`, `[turns]`, `[grid]`, `why` | перенести деталь, как мышью: клик в from, у to — `turns` (0–3) правых кликов и клик; в to придёт середина детали |
| `puzzle_give_up` | `why` | бросить головоломку, как по Esc |
| `save`, `load` | `slot` | служебное сохранение и загрузка, слоты 0–11 |

В квадратных скобках — необязательные. `why` — зачем действие, коротко
(подробно — словами героя в чате перед вызовом): без него действие не
принимается, а игра его не видит.

Ответ на действие — JSON: реплики (`said`), что прозвучало в головоломке
(`heard`), откликнулся ли мир (`reacted`), можно ли действовать дальше
(`ready`), что изменилось (`changes`) и что вокруг теперь (`look`); в
головоломке к нему приложена картинка. В `heard` — короткие слова по порядку
(«взял», «встало», «не туда», «съел», «победа»…), у органа — ноты с октавой
(«до3», «ми3», пустой раструб — «глухо»), ария Пятницы — «ария:» и её ноты по
порядку. Высоту нот один раз определил по звукам игры `tools/organnotes`, в
ремейке — только названия: сама игра звук не слушает, мелодии сравнивает
модель.

Сетка (`grid`) — линии через 40 px с подписями координат, x сверху, y слева;
она ложится только на картинку для модели, в окне игры её нет. Крупный план
(`region {x0,y0,x1,y1}` у `look`) — эта часть картинки, от 8×8 до 320×240,
увеличенная в целое число раз, сколько влезет в 640×480: так точнее целиться.
Сетка на нём чаще и подписана экранными координатами, а в ответе — показанная
область и увеличение (`scale`).

**Если не работает.** Клиент пишет, что сервер не запустился (`failed`), —
запустите ту же команду в терминале:

| Что видно | Что делать |
|---|---|
| окно с началом партии, терминал ждёт ввода | команда верна (закрыть — Ctrl+C): сверить с ней настройку клиента, пути — полные |
| `game resources not found` | `.mcp.json` из архива лежит не в папке игры; или путь к папке неверен или относительный, а клиент запускает сервер из своей папки |
| `no build for …` | для этой системы готовой сборки нет — собрать из исходников, см. [«Как запустить»](#как-запустить) |
| macOS не открывает файл | снять карантин — см. [«Как запустить»](#как-запустить) |
| логотип и меню, как в обычной игре | `-mcp` стоит после пути, а нужен до |

## Какие файлы игры нужны

Нужна вся папка с диска как есть. Файлы игры бинарник только читает, а
сохранения (12 слотов: `robinson00.sav`…`robinson11.sav` с миниатюрами `.png`)
пишет в ту же папку, поэтому она должна быть доступна на запись.

| Путь | Что берётся |
|---|---|
| `DATA/SCEN/*.DAN` | сцены: `.SCN` (сетка, объекты, звуки), `.OB` (объекты), `.FS` (анимации и логика) |
| `DATA/SCEN/*.DAT` | фоны сцен: `.NGB` + палитра `.COL` + таблица затемнения `.FAD` |
| `DATA/MOVIE/*.MV` | ролики: спрайты персонажей, предметов, анимации объектов |
| `DATA/WAVE/WAVE.DAN` | звук и музыка игры |
| `DATA/CHAR/ROBY.DAN`, `FRID.DAN` | персонажи: `.CHR` и циклы ходьбы `RG_XY`/`FG_XY` |
| `DATA/STARTUP.DAN` | `STARTUP.INF` (начальные переменные квеста) и `TEXT.DAT` (все тексты) |
| `DATA/BEGIN.BGI` | начальное состояние объектов в каждой сцене |
| `DATA/BAR/BAR.DAN`, `BAR.DAT` | панель инвентаря: раскладка `BAR.BAR` и её графика |
| `DATA/OPTIONS.DAT` | главное меню (оно же экран опций), экраны сохранения и загрузки |
| `LOGO.DAT` | логотип студии, титульный экран и экран «Загрузка» |
| `CRYPT.DAT`, `PIPE.DAT`, `HOUSE.DAT`, `MAP.DAT`, `CHESS.DAT`, `BALOON.DAT` | мини-игры |
| `MINIGAME.WDT` | звуки мини-игр |
| `ROBY.EXE` | только курсоры из его ресурсов, сам он не запускается |

Не используются: установщик (`SETUP.*`, `*.CAB`), остальные `*.EXE`, `*.DLL` (движок и
мини-игры переписаны), `DIRECTX/`, `DOCUMENT/` (там руководство `ROBY.PDF`),
`CONFIG.DAT`, `LANG.DAT`, `DATA/START.SAV`, а также `MINIGAME.SDT` и `*.MV` в
корне диска (антураж мини-игр, пока не подключён; из `SAMPLE.MV` взят только
Пятница у органа).

## Разработка

Игру для разработки положите в `extracted/ROBINSON_ISO/ROBINSON` (папка в
`.gitignore`): там её находят рецепты `just` и бинарник, запущенный из корня
репозитория.

```bash
just install-tools  # один раз: gofumpt, golines, golangci-lint
just check          # fmt + lint + test
just demo           # headless-прогон -> PNG-кадры
just scene PALACE   # кадр конкретной сцены
just puzzle-move 1  # puzzle_move на хижине (0 — на карте), без окна
```

`ROBINSON_TRACE` печатает в stderr каждую выполненную команду скриптов:

```bash
ROBINSON_TRACE=1 ./robinson                 # все команды
ROBINSON_TRACE=goscene,setvar ./robinson    # только переходы и флаги
```

Устройство — [ARCHITECTURE.md](ARCHITECTURE.md), форматы игры —
[docs/](docs/README.md), инструменты (реверс на Python, веб-сборка и отчёт по
квесту на Go) — [tools/](tools). План — [todo.md](todo.md).

## Ассеты

Код и инструменты — собственная работа, кроме `.vmdriver*` (производные от
Ebitengine, Apache-2.0); сторонние компоненты и их лицензии —
[THIRD_PARTY.md](THIRD_PARTY.md).

Графика, звук и тексты игры принадлежат правообладателю (Никита). В репозитории
и архиве релиза их нет. Веб-версия их тоже не содержит: она скачивает набор,
который `tools/packweb` упаковывает из вашей копии игры, с хоста данных
(`?data=` — любой другой источник, включая локальный `just web-serve`), а
фавикон `just build-wasm` берёт из `START.ICO` той же копии.
