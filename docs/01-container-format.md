# Формат контейнера `NL`

Все ресурсные файлы игры (`.DAN`, `.DAT`, `.MV`) — это один и тот же
контейнер-архив с сигнатурой `NL`. Внутри — директория записей и блок данных.
Загрузчик находится в `NGI32.DLL` (функция по адресу `~0x23270`, магия
проверяется в `0x232EF`).

## Общая раскладка файла

```
+0x00  заголовок               32 байта
+0x20  директория              count × 32 байта   (ЗАШИФРОВАНА)
+...   блок данных             csize_total байт   (записи по смещениям)
```

Инвариант, проверенный на всех 736 файлах:

```
filesize == 0x20 + count*32 + csize_total
```

## Заголовок (32 байта)

| Смещение | Тип | Имя | Описание |
|---|---|---|---|
| `0x00` | char[2] | magic | `"NL"` (`4E 4C`) |
| `0x02` | u8 | | `0x00` |
| `0x03` | u8 | version | `0x01` (проверяется: `[2]==0 && [3]==1`) |
| `0x04` | u16 | count | число записей в директории |
| `0x06` | u16 | count2 | дубликат `count` |
| `0x08` | u32 | | `0` |
| `0x0C` | u16 | flag | `0x0000` / `0x0005` / `0x0006` (см. ниже) |
| `0x0E` | u16 | marker | `0xABBA`, если `flag==0`; иначе `0x0001` |
| `0x10` | u32 | usize_total | суммарный распакованный размер |
| `0x14` | u32 | csize_total | суммарный хранимый размер **= ключ шифра** |
| `0x18` | u32 | | `0` |
| `0x1C` | u32 | | `0` |

Поле `flag` (`0x0C`) отражает преобладающий способ хранения записей, но
на распаковку не влияет — реальный метод берётся из каждой записи директории.
Загрузчик дополнительно проверяет `marker==0xABBA` в `0x23489`.

> **Важно:** значение `csize_total` (`0x14`) одновременно служит **ключом**
> для расшифровки директории. Это не совпадение — загрузчик читает ключ прямо
> из `[файл+0x14]`.

## Шифрование директории

Директория (`count` записей по 32 байта, начиная с `0x20`) зашифрована
8-битным потоковым шифром. Алгоритм снят дословно с `NGI32.DLL @0x2333B`:

```python
def decrypt_directory(buf):
    count = u16(buf, 0x04)
    key   = u32(buf, 0x14)          # ключ = поле csize_total
    al = key & 0xFF
    dl = (key >> 8) & 0xFF
    ct = buf[0x20 : 0x20 + count*32]
    out = bytearray(len(ct))
    for i, c in enumerate(ct):
        al = ((al << 1) & 0xFF) ^ dl
        dl = (dl >> 1) & 0xFF
        out[i] = c ^ al
        dl = (dl ^ al) & 0xFF
    return bytes(out)
```

Состояние шифра — всего два байта (`al`, `dl`), инициализируются младшими
двумя байтами ключа. Гаммой служит `al`; `dl` эволюционирует с обратной связью
от `al`. Блок данных **не** шифруется (только сжимается).

Оригинал на ассемблере (для сверки):

```asm
mov  edx, [ebp+0x14]     ; edx = key
mov  al, dl              ; al = key & 0xFF
shr  edx, 8              ; dl = (key>>8)&0xFF
.loop:
  mov  bl, [ecx+ebp+0x20]  ; шифртекст
  shl  al, 1
  xor  al, dl
  shr  dl, 1
  xor  bl, al              ; -> открытый байт
  xor  dl, al
  mov  [ecx+esi], bl
  inc  ecx
  cmp  ecx, <count*32>
  jl   .loop
```

## Запись директории (32 байта, после расшифровки)

| Смещение | Тип | Имя | Описание |
|---|---|---|---|
| `0x00` | char[12] | name | имя `"ИМЯ.EXT"`, дополнено `\0` |
| `0x0C` | u32 | reserved | `0` (не используется загрузчиком) |
| `0x10` | u16 | method | метод `ngiUnpack` (`0`, `0x40`, `0x80`, `0x100`) |
| `0x12` | u16 | id | порядковый id записи внутри архива |
| `0x14` | u32 | usize | распакованный размер |
| `0x18` | u32 | offset | **абсолютное** смещение данных в файле |
| `0x1C` | u32 | csize | хранимый (сжатый) размер |

Если `usize == csize`, запись хранится без сжатия (метод `0`). Иначе
`method` задаёт кодек — см. [02-compression.md](02-compression.md).

Поле `method` — это тот самый флаг, который в рантайме кладётся в структуру
`RsLi` (см. ниже) по смещению `+0x10` и разбирается `ngiUnpack` по битам
`& 0x1E0`, `& 0x80`, `& 0x40`.

## Рантайм-структура `RsLi`

На диске формат называется `NL`; в памяти загрузчик разворачивает его в
структуру с сигнатурой `"RsLi"` (`0x694C7352`) — заголовок `0x38` байт и
записи по `0x40` байт. Именно её принимает `ngiUnpack`. Для распаковки файлов
знать `RsLi` не обязательно (мы читаем `NL` напрямую), но это объясняет, почему
в `NGI32.DLL` магия `"RsLi"` встречается 32 раза, а `"NL"` — лишь в загрузчике.

Соответствие полей `NL`-записи → `RsLi`-записи:

| `RsLi` +off | источник из `NL` |
|---|---|
| `+0x00` (name[12]) | `name` |
| `+0x10` (method/flags) | `method` |
| `+0x1C` (usize) | `usize` |
| `+0x24` (data ptr) | `file_base + offset` |
| `+0x28` (csize) | `csize` |
