# Типы ресурсов

Записи внутри `NL`-контейнеров различаются по расширению в имени. Сводка по
всему образу (28 053 записи в 736 контейнерах):

| Ext | Записей | Метод | Что это |
|---|--:|---|---|
| `NGB` | 19 915 | `0x80` (в осн.) | растровая графика (кадры, фоны, спрайты) |
| `FS` | 5 166 | `0x40` | кадровый скрипт анимации (текст) |
| `WAV` | 1 105 | `0x00` | звук, RIFF PCM 22050 Hz/16 бит/моно |
| `COL` | 698 | `0x80` | палитра, 256×RGBA (1024 байта) |
| `SCR` | 646 | `0x80` | скрипт ролика (бинарный) |
| `OB` | 438 | `0x40` | описание объекта сцены (текст) |
| `FAD` | 38 | `0x80` | таблица затемнения (fade LUT) |
| `SCN` | 37 | `0x40` | описание сцены (текст) |
| `CHR` | 2 | `0x40` | описание персонажа (Roby, Friday) |
| `LST` | 2 | `0x40` | список |
| прочее | | | `TXT`, `NFT`, `INF`, `BAR`, `DAT` |

## `WAV` — звук

Хранится без сжатия (метод `0x00`) в едином архиве `DATA/WAVE/WAVE.DAN`
(1050 файлов, 115 МБ). Каждая запись — готовый RIFF/WAVE: PCM, моно, 22050 Hz,
16 бит. Извлекается побайтовой копией и сразу играется. Имена — `A01A.WAV`,
`RR447.WAV`, `RSOK2.WAV` и т. п.; на них ссылаются скрипты командой `Sound`.

## `COL` — палитра

1024 байта = 256 записей по 4 байта в формате **Windows `RGBQUAD`**: порядок
байтов `B, G, R, reserved` (4-й всегда `0`). **Каналы идут как BGR, не RGB** —
при рендере нужно поменять местами R и B, иначе всё «отдаёт синевой» (тёплые
цвета становятся холодными: кожа синеет, песок синеет). Индекс в палитре — это
значение пикселя в `NGB`. У каждого ролика/экрана своя палитра (`ARRI0001.COL`,
`OPTIONS.COL`, …).

**Спрайты сцены красятся палитрой сцены, `.COL` ролика не читается.** Контекст
экрана сцены получает одну палитру — `ngiSetPalette(0, 0xffffff00, scene+0x38)`
(`ROBY.EXE 0x414aa0`), а `FonScript::Render` (`0x4165b0`) грузит кадр как
`rsLoad(lib, frame+2)`, пропуская запись 1 (`.COL`). Так рисуются все объекты,
Роби, Пятница и ролики-действия. У панели свой контекст с `BAR.COL`. Все игровые
сцены делят одну палитру, у INT1–INT4 свои. Почти все ролики несут другую
палитру — у объектов-вырезок из фона (дуб SCENA1, идолы PALACE, двери SHIP1…)
пиксели в индексах сцены, и в своей палитре они выходят светлыми пятнами.

## `NGB` — Nikita Graphics Bitmap

8-битное палитровое изображение. Заголовок 16 байт:

| Смещение | Тип | Описание |
|---|---|---|
| `0x00` | u32 | `0` (флаг/тип) |
| `0x04` | u16 | `dimA` — ширина − 1 (макс. X) |
| `0x06` | u16 | `dimB` — высота − 1 (макс. Y) |
| `0x08` | u16 | тип: `0` = сплошной битмап, `256` = спрайт с прозрачностью |
| `0x0A` | u16 | `0` |
| `0x0C` | u32 | сигнатура `~0x01EFCDAB` (у фонов `0x01F0CDAB`) |

Дальше — два подтипа:

### Подтип A: сплошной битмап (`@0x08 == 0`)

Сразу после заголовка — `width × height` байт индексов палитры, построчно.
Пример: полноэкранные экраны меню `OPTIONS.NGB`/`SAVE.NGB`/`LOAD.NGB` =
`16 + 640×480 = 307216` байт, `dimA=639`, `dimB=479`. Рендер тривиален:
`pixel = palette[index]`.

### Подтип B: спрайт с прозрачностью (`@0x0C == 0x01EFCDAB`)

Заголовок — тот же bbox `x0,y0,x1,y1`. Сразу за заголовком (с `0x10`) идёт
**таблица смещений строк**: `height` записей `u32`, где `table[y]` — абсолютное
смещение данных строки `y` от начала NGB. Каждая строка — последовательность
**прогонов** (runs); прогон = `u32`-заголовок, затем `count` байт пикселей:

```
skip  = header & 0xFFFF      # прозрачных пикселей перед прогоном
count = header >> 16         # непрозрачных пикселей (столько байт следом)
конец строки: (header & 0x8000) установлен
```

Грамматика снята дословно с `ngiGetNgbPixel` (`NGI32.DLL @0xF7F0`, RLE-ветка
`@0xF84F`) и реализована в [`../tools/ngb.py`](../tools/ngb.py). Проверено
рендером: спрайты декодируются корректно (персонажи, объекты сцен). Прозрачные
пиксели → alpha=0; непрозрачный индекс, равный `transparent` из заголовка, тоже
считается дырой.

> Полностью разобран — оба подтипа NGB рендерятся корректно.

## `FAD` — таблица затемнения

**Вскрыта.** Файл — это N подряд идущих таблиц по 256 байт: шаг k отображает
каждый индекс палитры в более тёмный. У сцен 4096 байт = **16 шагов**
(`TEMP.FAD` в `OPTIONS.DAT` — 8192 = 32 шага). Шаг 0 почти тождественный,
последний переводит всё в чёрный: средняя яркость палитры падает монотонно
(для `SCENA0.FAD`: 95 → 89 → 83 → … → 0).

Так оригинал гасит 8-битный экран, не трогая пиксели. В ремейке кривая шагов
(средняя яркость каждого шага, нормированная на первый) используется как
коэффициент затемнения кадра — тот же тайминг и та же нелинейность.

## `CHR` / `LST` — персонаж и списки

`ROBY.DAN` и `FRID.DAN` описывают двух персонажей (Робинзон и Пятница). Внутри:
`ROBY.CHR` (описание), множество `.FS` (кадровые скрипты поз/действий) и
`DO.LST` (инвентарь циклов ходьбы). Оба — метод `0x40` (текст).
Подробно — [09-characters.md](09-characters.md).

## `BAR.BAR` + `BAR.DAT` — панель инвентаря

`DATA/BAR/BAR.DAN:BAR.BAR` — текстовая раскладка панели: `BarLTWH 0,400,640,80`
(панель занимает нижние 80 px экрана 640×480), `InventoryLTWH 303,410,146,60`,
`ItemWH 48,60`, `ItemsDisplayed 3`, боксы портрета, текста, стрелок, карты и
сохранения, плюс список `Items` из 33 предметов.

`DATA/BAR/BAR.DAT` — её графика, 83 спрайта: `BAR0` (фон 640×80), `BAR1..BAR3`
(кнопка-портрет: дуо с активным Роби, дуо с активной Пятницей, один Роби), `BAR4`
(плашка текстового поля), `BAR5` (рамка, обрезающая окно инвентаря, кладётся по
`InvMaskLT` поверх иконок), `BAR6..BAR71` — пары «обычная/выбранная» иконки на все
33 предмета `Items`, `BAR72..BAR74` (кнопка карты: доступна, нажата, пустая — пока
карта не открыта), `BAR75/BAR76` (дискета: обычная, нажатая), `BAR77..BAR82`
(стрелки прокрутки: погашенная, зажжённая, пустая — по одной тройке на сторону).

Фон `BAR0` — не просто картинка: под портретом и обеими кнопками у него **прозрачные
вырезы**, так что кнопки обязательно рисовать, иначе на их месте дыра. Погашенные
стрелки, наоборот, впечатаны в фон — сверху кладётся только зажжённая (`BAR78`
слева, `BAR81` справа, вплотную к внешнему краю своего бокса).

Команда кнопки карты лежит в `ROBY.EXE` рядом с таблицей ключей раскладки:
`GoScene MAPSCR, Roby, Roin0, Frid, Frin0, 0,0`. Входные скрипты обязательны —
`MAPSCR:ROIN0.FS`/`FRIN0.FS` ставят обоих героев в клетку `7,0` (якорь x=1015,
за краем экрана; клетка отрезана `ClosedVert`) и делают `SetMap OFF`. Без них на
карте стоят персонажи, она проходима, а кнопка остаётся зажжённой.

Кнопка-дискета по руководству (ROBY.PDF, стр. 27) открывает **главное меню**
игры (`OPTIONS.DAT`), а не отдельный экран сохранения — сохранение там пункт
меню.

## `OPTIONS.DAT` — меню, экраны сохранения и загрузки

19 записей и **три разные палитры**, и это главный подвох пакета.

| запись | что это | палитра |
|---|---|---|
| `OPTIONS.NGB` 640×480 | главное меню (оно же экран опций) | `OPTIONS.COL` |
| `OPTS0..OPTS4` 236×34 | подсвеченные строки меню, координаты в их же bbox: `(214,62)`, `(214,104)`, `(214,147)`, `(214,190)`, `(214,233)` | `OPTIONS.COL` |
| `OPTS5` 29×29 | движок ползунка | `OPTIONS.COL` |
| `SAVE.NGB` / `LOAD.NGB` 640×480 | экраны сохранения и восстановления | `SAVE.COL` |
| `BUT20` 240×35 `(41,436)` / `BUT21` 239×35 `(362,436)` | «Сохранение» и «Отмена» экрана **сохранения**, нажатое состояние | `SAVE.COL` |
| `BUT10` 239×35 `(41,436)` / `BUT11` 240×35 `(362,436)` | «Восстановление» и «Отмена» экрана **загрузки**, нажатое состояние | `SAVE.COL` |
| `TEMP.NGB` 129×98 + `TEMP.COL` + `TEMP.FAD` | пустой слот (мрамор) и его 32-шаговая таблица затемнения | `TEMP.COL` |

`SAVE.COL`, `LOAD.COL` и `TEMP.COL` побайтово одинаковы, а вот с `OPTIONS.COL`
у них **не совпадает ни одна из 256 записей**: `OPTIONS.COL` — тёплая охра с
19 серыми тонами, `SAVE.COL` — чистая сепия с золотом, где нет ни одного
красного и всего четыре серых. Кнопка `BUT*`, покрашенная палитрой меню,
превращается в серо-жёлтую кашу (~40 % пикселей уходит в серый), поэтому
палитру в пакете выбирают по имени битмапа, а не одну на всех.

`BUT*` — это **вдавленное** состояние: каждая кнопка совпадает со своей
подложкой, сдвинутой на пиксель вправо и вниз (совпадение меток 98 %), тогда
как выпуклая версия уже впечатана в `SAVE.NGB`/`LOAD.NGB`. Отсюда и поведение:
спрайт кладут, пока держат левую кнопку мыши, а действие выполняют на
отпускании.

Слоты — таблица `ROBY.EXE @0x46d1f0`: 12 окон 128×96 от `(16,50)` с шагом
160×130, ровно проёмы рамок на `SAVE.NGB`/`LOAD.NGB`. Миниатюру оригинал снимает
при открытии меню (`0x405fc0`): контекст сцены (640 × высота сцены, без панели)
растягивается в 128×96 и пишется рядом с сейвом как `<N>.ngb` (`0x4087a0`).
Выбранный слот рисуется как есть, остальные — через `.FAD` текущей сцены с долей
0.4 (шаг ⌊(N−1)·0.4⌋ = 6 из 16), пустой — `TEMP.NGB`, притемнённый шагом 12 из
32 `TEMP.FAD`. Рамок и подсветки наведения нет; слот выбирают кликом, при
открытии меню выбран первый.

## Сейвы: `.SAV` / `.BGI`

`DATA/START.SAV` и `DATA/BEGIN.BGI` — **побайтово идентичны** (по 161 980 байт),
это стартовое состояние «новой игры». **Не** `NL`-контейнеры: плоский дамп
состояния.

Разобрана главная часть — **начальное состояние объектов**. Файл содержит
подряд идущие записи по 36 байт: имя объекта (20 байт, дополнено нулями) и
четыре `int32` — `gx`, `gy`, `z`, `visible`. Записи идут кластерами: один
кластер = `ObjectList` одной сцены, в порядке списка сцен из `STARTUP.INF`
(сцену определяют по совпадению имён). Именно этот флаг решает, что на старте
игры камни и костёр на пляже не видны, а вождь во дворце — один: скрытые
объекты ждут своего `CreateObject`.

Персонажей сейв оригинала пишет по записи на каждого (`0x41fba0`): кроме
прочего клетку (`+0x254`/`+0x258` — туда же пишут `Set char,X|Y`), `z`
(`+0x25c`) и флаг скрытия `+0x73c` (`HideChar`/`ShowChar`). Загрузка входных
скриптов не запускает, так что без этих полей Пятница после загрузки
пропадала бы.

Свой сейв ремейк пишет в собственном формате (JSON + миниатюра кадра); клетку,
`z` и видимость Пятницы хранит поле `frid`. В старых сейвах его нет: тогда
видимость берётся из `FridIs`, а Пятница встаёт в соседнюю с героем клетку.

## Служебные текстовые файлы (не `NL`)

- `AUTORUN.INF` — автозапуск (`OPEN=START.EXE`).
- `DATA.TAG` — метаданные (`Company=Nikita`, `Application=New Robinson`).
- `CONFIG.DAT` — 4 байта, текущий конфиг.
- `OS.DAT`, `LANG.DAT`, `SETUP.*` — данные инсталлятора InstallShield.
- `DEMO.DAT` — сценарий демо-режима: список роликов (`rohangol`, `dehancro`, …).
- `DOCUMENT/ROBY.PDF` — руководство пользователя (PDF, 44 стр.): гл. 5–6 —
  первоисточник поведения меню, панели и мини-игр; сверка ремейка с ним — в
  [../todo.md](../todo.md), этап 8.
