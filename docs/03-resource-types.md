# Типы ресурсов

Записи внутри `NL`-контейнеров различаются по расширению в имени. Сводка по
всему образу (28 053 записи в 736 контейнерах):

| Ext | Записей | Метод | Что это |
|---|--:|---|---|
| `NGB` | 19 915 | `0x80` (в осн.) | растровая графика (кадры, фоны, спрайты) |
| `FS` | 5 166 | `0x40` | кадровый скрипт анимации (текст) |
| `WAV` | 1 105 | `0x00` | звук, RIFF PCM 22050 Hz/16 бит/моно |
| `COL` | 698 | `0x80` | палитра, 256×RGBA (1024 байта) |
| `SCR` | 646 | `0x80` | скрипт ролика (бинарный) |
| `OB` | 438 | `0x40` | описание объекта сцены (текст) |
| `FAD` | 38 | `0x80` | таблица затемнения (fade LUT) |
| `SCN` | 37 | `0x40` | описание сцены (текст) |
| `CHR` | 2 | `0x40` | описание персонажа (Roby, Friday) |
| `LST` | 2 | `0x40` | список |
| прочее | | | `TXT`, `NFT`, `INF`, `BAR`, `DAT` |

## `WAV` — звук

Хранится без сжатия (метод `0x00`) в едином архиве `DATA/WAVE/WAVE.DAN`
(1050 файлов, 115 МБ). Каждая запись — готовый RIFF/WAVE: PCM, моно, 22050 Hz,
16 бит. Извлекается побайтовой копией и сразу играется. Имена — `A01A.WAV`,
`RR447.WAV`, `RSOK2.WAV` и т. п.; на них ссылаются скрипты командой `Sound`.

## `COL` — палитра

1024 байта = 256 записей по 4 байта в формате **Windows `RGBQUAD`**: порядок
байтов `B, G, R, reserved` (4-й всегда `0`). **Каналы идут как BGR, не RGB** —
при рендере нужно поменять местами R и B, иначе всё «отдаёт синевой» (тёплые
цвета становятся холодными: кожа синеет, песок синеет). Индекс в палитре — это
значение пикселя в `NGB`. У каждого ролика/экрана своя палитра (`ARRI0001.COL`,
`OPTIONS.COL`, …); персонажи рендерятся в палитре своего ролика.

## `NGB` — Nikita Graphics Bitmap

8-битное палитровое изображение. Заголовок 16 байт:

| Смещение | Тип | Описание |
|---|---|---|
| `0x00` | u32 | `0` (флаг/тип) |
| `0x04` | u16 | `dimA` — ширина − 1 (макс. X) |
| `0x06` | u16 | `dimB` — высота − 1 (макс. Y) |
| `0x08` | u16 | тип: `0` = сплошной битмап, `256` = спрайт с прозрачностью |
| `0x0A` | u16 | `0` |
| `0x0C` | u32 | сигнатура `~0x01EFCDAB` (у фонов `0x01F0CDAB`) |

Дальше — два подтипа:

### Подтип A: сплошной битмап (`@0x08 == 0`)

Сразу после заголовка — `width × height` байт индексов палитры, построчно.
Пример: полноэкранные экраны меню `OPTIONS.NGB`/`SAVE.NGB`/`LOAD.NGB` =
`16 + 640×480 = 307216` байт, `dimA=639`, `dimB=479`. Рендер тривиален:
`pixel = palette[index]`.

### Подтип B: спрайт с прозрачностью (`@0x0C == 0x01EFCDAB`)

Заголовок — тот же bbox `x0,y0,x1,y1`. Сразу за заголовком (с `0x10`) идёт
**таблица смещений строк**: `height` записей `u32`, где `table[y]` — абсолютное
смещение данных строки `y` от начала NGB. Каждая строка — последовательность
**прогонов** (runs); прогон = `u32`-заголовок, затем `count` байт пикселей:

```
skip  = header & 0xFFFF      # прозрачных пикселей перед прогоном
count = header >> 16         # непрозрачных пикселей (столько байт следом)
конец строки: (header & 0x8000) установлен
```

Грамматика снята дословно с `ngiGetNgbPixel` (`NGI32.DLL @0xF7F0`, RLE-ветка
`@0xF84F`) и реализована в [`../tools/ngb.py`](../tools/ngb.py). Проверено
рендером: спрайты декодируются корректно (персонажи, объекты сцен). Прозрачные
пиксели → alpha=0; непрозрачный индекс, равный `transparent` из заголовка, тоже
считается дырой.

> Полностью разобран — оба подтипа NGB рендерятся корректно.

## `FAD` — таблица затемнения

8192 байта, начинается с последовательности `00 01 02 03 … 0F …` (тождественное
отображение) — это lookup-таблица для плавного затемнения/высветления палитры
(эффекты `Fade`). Используется движком при переходах между сценами.

## `CHR` / `LST` — персонаж и списки

`ROBY.DAN` и `FRID.DAN` описывают двух персонажей (Робинзон и Пятница). Внутри:
`ROBY.CHR` (описание), множество `.FS` (кадровые скрипты поз/действий) и `.LST`
(список). `CHR`/`LST` — метод `0x40` (текст).

## Сейвы: `.SAV` / `.BGI`

`DATA/START.SAV` и `DATA/BEGIN.BGI` — **побайтово идентичны** (по 161 980 байт),
это стартовое состояние «новой игры». **Не** `NL`-контейнеры: плоский дамп
состояния — таблица полей, имена звуков (`step.wav`), CP1251-строки и значения
игровых переменных (`IntVariables`/`CharVariables`/`TextVariables`). Полная
байтовая схема для ремейка не нужна — сейв проектируется свой.

## Служебные текстовые файлы (не `NL`)

- `AUTORUN.INF` — автозапуск (`OPEN=START.EXE`).
- `DATA.TAG` — метаданные (`Company=Nikita`, `Application=New Robinson`).
- `CONFIG.DAT` — 4 байта, текущий конфиг.
- `OS.DAT`, `LANG.DAT`, `SETUP.*` — данные инсталлятора InstallShield.
- `DEMO.DAT` — сценарий демо-режима: список роликов (`rohangol`, `dehancro`, …).
- `DOCUMENT/ROBY.PDF` — руководство пользователя (PDF, 1.8 МБ).
